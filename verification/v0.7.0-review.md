## Corrections and evidence

Interface requirements now use `let name = function(...): Type;`. The parser
stores a name/signature declaration without evaluating or allocating a function
value. Ordinary function expressions and implementation methods still require
bodies. The old requirement spelling, interface bodies, `var`, aliases and
arbitrary expressions are parse errors. Conformance, method identity, receiver,
dispatch, value layout and ABI remain unchanged by this syntax correction.

Before the native fixes, an equivalent interface-dispatch program compiled to
exactly the same 4,440 ELF bytes with the old and new requirement spelling.
This comparison isolated the parser change; padding and table-order corrections
subsequently change generated code/layout while preserving dispatch semantics.

All three implementation-review findings were reproduced against the baseline:

- Removing only the payload-free parenthesis guard in memory left the old
  `E::A()` tail rejected for entry type mismatch. A binding followed by `true`
  passed the mutated semantic checker. Constructor rejection fixtures now use
  valid bool tails and have corresponding accepted constructions.
- A real collected block retained nonzero unused words when reused by an empty
  constructor. Helpers now clear the entire physical payload before slot fill
  and publication, including minimum empty storage and unsplit remainder space.
- Reversed implementation declarations emitted tables in source order. Only
  an output copy is now sorted by concrete type ID, then interface ID; the
  source-order registry and implementation IDs are preserved.

suite after correction passed 20 groups, 2,487 assertions and 135 processes,
with zero failures. Existing dispatch, lifetime, ABI and corruption groups are
retained and migrated to the new spelling.
