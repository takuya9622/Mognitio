## Generic type checking

Generic struct, enum, and alias declarations are checked under rigid type
parameters. Full argument arity, alias-normalized invariant identity, parameter
usage and shadowing, source order, and the concrete argument domain are enforced.
The canonical Result template is predeclared. Implementations cannot target a
generic nominal instance through aliases; ordinary aggregates containing generic
fields remain valid targets.

Symbolic template terms stay separate from concrete type descriptors. Concrete
children are resolved before assigning their parent descriptor ID. The independent
verifier reconstructs templates and aliases and checks instantiated fields,
arguments, builtin identity, instance registry, and declaration order. Corruption
tests cover each of these boundaries.

Validation: sbcl --noinform --script scripts/test.lisp passed with
164 groups, 18,048 assertions, 1,515 child processes, zero failures.
git diff --check and the tracked-file checksum manifest passed. New generic
checks establish the type-analysis boundary; function specialization and generic
runtime conformance are still pending.

## Generic function templates

All generic bodies are checked at declaration time under rigid type parameters.
Named generic calls require full explicit arguments; direct static aliases retain
the original declaration identity. Templates cannot appear as runtime values.
Generic bindings complete with void and retain lexical scope and source order.
Nested functions may refer to outer type parameters while runtime capture stays
prohibited. Declaration call graphs include generic calls without splitting
targets by type arguments.

The independent verifier reconstructs parameter scopes, binding classification,
explicit call substitutions, lexical owners, and declaration edges. Mutations
of rigid signature types, parent ownership, template markers, completion, and
call arguments are rejected.

Validation: sbcl --noinform --script scripts/test.lisp passed with
167 groups, 18,480 assertions, 1,515 child processes, zero failures.
git diff --check and the tracked-file checksum manifest passed. This establishes
the template analysis boundary; concrete instance generation and execution of
generic functions are not yet complete.

## Concrete instances and backend integration

Verified templates now produce concrete function and type instances in canonical
key order. Instance keys include transitive free outer type parameters. Each
instance receives fresh AST nodes and checked tables, with local, loop, callee,
method receiver, and return identities remapped together. Generic declarations
and aliases are erased from runtime sequences while tails and control flow remain.
Unused templates generate no functions, including otherwise independent children.

The independent instance verifier decodes keys against source declarations,
checks AST correspondence and erasure, reconstructs substitutions, validates all
runtime metadata, and rejects extra or missing instances. Both backends use this
gate. Core descriptor verification checks the type graph for cycles instead of
assuming that canonical runtime IDs follow declaration dependencies.

Run and native tests cover alternating primitive instances, nested functions,
transitive lexical type dependencies, instance sharing, void payloads, generic
data, interface methods, loop/return owners, GC survival, deterministic output,
and corruption of instance keys, bindings, callees, ASTs, and checked metadata.

Validation: sbcl --noinform --script scripts/test.lisp passed with
171 groups, 18,875 assertions, 1,581 child processes, zero failures.
git diff --check and the tracked-file checksum manifest passed.

## Try and panic execution

Try records the lexical return owner and canonical Result identities. Err
reconstructs the enclosing function result type, including when success types
differ. Both enum payload reads are protected by positive tag guards. Panic
reuses ordinary block evaluation and emits a terminal operation only on its
normal string path. Earlier return, break, continue, panic, and runtime failure
propagate without an outer panic. Independent template and instance verification
checks these records and all owner/type substitutions.

The native panic terminal participates in liveness and frame verification. Its
private ABI reserves one outgoing argument slot. The nonallocating reporter
writes the evaluated message in three byte segments, handles partial writes and
bounded EINTR retries, and always exits 4 even when reporting fails. The host
condition retains the message and follows the same stream/status contract.

Validation: sbcl --noinform --script scripts/test.lisp passed with
179 groups, 19,603 assertions, 1,654 child processes, zero failures.
Targeted tests cover lexical owners, opaque forwarding, void payloads, earlier
control transfer, UTF-8/NUL messages, garbage collection, terminal roots, native
frame corruption, output fault injection, build nonexecution, and artifact
preservation. git diff --check and the tracked-file checksum manifest passed.
