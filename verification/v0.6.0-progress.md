# v0.6.0 development progress

This is an implementation-start record, not a completion or release record.
The starting implementation is `4596dc4dc28fa8bc1c1b73eb3debb19e9fee95bb`.

## Implemented increment

- String literal scanning, decoded UTF-8 payloads, postfix method AST nodes,
  string types, and typed operation records.
- Independent CheckedProgram validation of operation kind, ordered operands,
  signature, result, and early-exit summaries.
- Host text objects, scalar length/slicing, content equality, copy concatenation,
  and ordered Common Lisp forms with caller control-flow targets.
- Shared runtime failure base, retained integer subtype, prebuilt diagnostics,
  and separately classified program/compilation storage failures.

## Validation and reproduction

Run `sbcl --noinform --script scripts/test.lisp` and `git diff --check`.
The pre-change baseline passed 94 groups, 12,933 assertions, and 1,141 child
processes. This increment adds ten groups. Three historical groups containing the newly
reserved identifier `string` have explicit migrated replacements; their original
fixture file remains unchanged. The replacement retains every unrelated case.
Exact reviewed commits, commands, and final suite results are recorded in the
pull request; the content manifest identifies the delivered files.

The host GC child can also be run directly:

```sh
sbcl --dynamic-space-size 256 --noinform --script tests/v06-host-gc-entry.lisp
```

On SBCL 2.6.0.debian / ASDF 3.3.1, the 256 MiB child allocated 1,179,779,072
payload bytes in 9,001 allocations. All 9,001 weak references were dead after
full GC, and the separately held three-byte value retained its contents.
Observed resident dynamic usage after compilation was 33,180,896 bytes.
The test asserts measured allocation and weak-reference outcomes; collection
counts alone are not used as proof. Test-only wrappers hold no strong references
to the dynamic results.

Static negative tests exercise both run and build, including existing output
preservation. Successful text execution, scalar-oracle comparisons, injected
runtime failures, and text reclamation currently exercise the host backend only.
All successful host samples finish with the existing boolean output contract.

## Remaining work

Native text runtime helpers and mark-and-sweep, native finite-heap evidence and failure injection, cross-backend
acceptance, and text artifact regression remain unimplemented/unverified.
The existing native backend may reject otherwise valid text programs as an
internal missing-runtime failure. This intermediate development
snapshot must not be treated as native text support or a v0.6.0 release.

## Diagnostic failure follow-up

The double-failure child reproduces an allocation failure followed by a
storage condition while writing its runtime diagnostic. Diagnostic handlers now
catch that condition explicitly: runtime failure retains exit 4, and failed
compiler/source diagnostic delivery returns exit 3. The child checks empty
output and marks any execution of the subsequent arithmetic with exit 99.
A separate concat test isolates scalar-count overflow after the byte-size check
and before payload allocation, without constructing a huge payload.

## Core and root planning increment

Core now carries string SSA values, deterministic UTF-8 literal pool IDs, typed
text operations, and checked allocation/failure/call-barrier effects. Lowering
preserves source order and stops after early exits. It retains unused allocating
operations and leaves nonselected branch operations inside their blocks.

`root-analysis.lisp` computes block live-in/live-out to a fixed point, translating
successor parameters to incoming values on each edge. Each allocating operation
gets sorted string value IDs; list positions are root slot numbers. Capacity is
the largest set in the function. Last-use arguments are included, the operation's
result is excluded, and integer/function/dead values are not roots.
`root-verifier.lisp` independently solves an instruction graph and checks exact
sites, sets, slot order, owners, and capacities. Both analyses handle cycles and
no-exit SCCs. Register allocation treats all text helpers as call barriers,
including nonallocating equality and length operations.

The Core tests include a separate character-sequence interpreter, explicit source
results, and 21 bounded loop cases. Handwritten root fixtures and corruption tests
cover edge substitution, caller arguments, receiver/earlier operand survival,
last-use values, dead parameters, result-before-definition, wrong types,
duplicates, extra/missing sites, and incorrect frame capacities. Repeated operands
are tested as one root slot. Producer/verifier agreement alone is not the oracle.

Root plans are available through `mognitio.roots:analyze-roots` and are consumed
by machine root-frame publication. No Core test substitutes for
native ABI, pointer survival, or collector reclamation evidence.

## Literal pool contract correction

The pool always reserves ID zero for empty text, even without an empty literal.
Nonempty payloads are collected from all checked literal nodes in source-span
order before lowering, so nested function bodies and entry expressions share
the same ordering. Lowering only looks up established IDs. Core verification
rejects a missing/nonempty zero entry and duplicate payloads. Tests fix the
expected IDs independently and cover nested functions and sources without text.

## Native ABI and root publication increment

The native target uses internal ABI v3. The entry stub reads AT_PAGESZ from the
initial stack, reserves a zeroed 32-byte context below it, and keeps its address
in R15. Source functions retain one probed frame with separate spills, parallel
copy storage, root header/slots, and outgoing arguments (including helper arity).
Each safepoint clears every root slot, copies required homes, places arguments,
and calls. The epilogue restores the previous root head without changing RAX.

Machine validation checks frame ranges and actual emitted sections against the
Core root plan, including stack probes, link/unlink, complete slot clearing,
value homes, publication before calls, argument placement, call targets, and
unannotated calls. The encoder supports R15/general base access, byte access,
unsigned branches, and text-symbol RIP-relative fixups. Static objects appear
in pool order with 8-byte alignment, flags 5, and zero padding.

Six new groups exercise hand-reviewed bytes, object layout and determinism,
corrupted frame evidence, and handwritten/generated ABI pairs with string,
void, int, and bool arguments. A 100-iteration helper probe checks shrinking
root sets, zeroed surplus slots, caller-clobbered registers, and return handoff.
An independent process reports the OS page size used by the context check.
The two historical entry-prefix goldens change because the entry now saves the
initial stack and initializes context; their ELF and output checks remain.

The helper probes are test-only and return existing arguments; they do not
implement concatenation, slicing, or collection. Production rejects required
text helpers until the real runtime is provided. These probes establish ABI
and root publication evidence, not native text semantics or GC safety.
