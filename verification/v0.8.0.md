# v0.8.0 implementation validation

This historical record covers version-branch implementation and verification.
Subsequent review and release checks are in [release validation](v0.8.0-release.md).

## Identity and commands

The implementation started from v0.7.0 revision
`ac5b116ed011d515d9137c730ce3ac41f3e05fde`. Its cumulative baseline passed
156 groups, 17,510 assertions and 1,501 child processes with zero failures.
The incremental results are in [development progress](v0.8.0-progress.md).

The final source is identified by the PR head, Git tree and
[content manifest](SHA256SUMS). The independently recorded CLI observations
include their exact compiler head in [acceptance results](v0.8.0-results.json).
Evidence-only changes after that measurement do not change compiler or fixture
bytes. The merged version-branch tree is compared with the tested PR tree.

```sh
sbcl --noinform --script scripts/test.lisp
python3 scripts/verify-v08.py --output /tmp/v08-results.json
git diff --check
sha256sum -c verification/SHA256SUMS
```

Environment: non-root Linux amd64, SBCL 2.6.0.debian, bundled ASDF 3.3.1,
Python 3.14.4, and ptrace access to test-owned children.

Final cumulative result: 184 groups, 21,501 assertions,
1,797 child processes, zero failures. This includes all prior regression
groups and README examples. UTF-8, LF, Markdown links/fences, whitespace and
the delivered-file manifest also passed.

## Source acceptance mapping

All 55 IDs (C08-01 through C08-34 and C08-40 through C08-60) have independent
fixtures in `tests/v08-conformance.lisp`. The [catalog](v0.8.0-cases.json)
contains 156 source hashes and expected outcomes. No retired ID is reused.

| IDs | Observations |
|---|---|
| 01–07 | Argument domain, substitution, aliases, syntax, invariant identity, arity/scope and recursive type rejection |
| 08–16 | Explicit calls, token-only commitment, alias chains, excluded callees, no inference and pattern checks |
| 17–21 | Canonical Result construction, ordinary Err values, explicit error conversion, void slot and identity |
| 22–30 | One evaluation, early return, differing success types, cross-function propagation, branch equivalence, lexical owners and failure priority |
| 31–34 | Mixed/all panic arms, suppressed operands, earlier control transfer, block syntax and runtime output |
| 40–44 | Generic payload lifetime, static restrictions, regressions, artifact behavior and backend agreement |
| 45–54 | Explicit declarations, static aliases, pattern bindings, opaque parameters, capture and reserved words |
| 55–60 | Implement target boundary, generic forwarding, noncompleting initializers, block panic and template erasure |

The CLI evidence records 67 executable fixtures and 89 rejection fixtures.
Each executable fixture has run/native status and output byte equality, a
standalone artifact hash, and byte-identical repeated builds. Each rejection
records the run/build diagnostic phase and preservation of an existing output.
Additional focused tests cover behaviors within an ID that need multiple
independent observations. No acceptance ID is left unexecuted or host-only.

## Internal boundaries

| Boundary | Independent checks |
|---|---|
| Frontend and bindings | ASTs, spans, whitespace commitment, malformed syntax and declaration categories |
| Opaque templates | Rigid signatures, lexical scopes, declaration call cycles, unused bodies and template value rejection |
| Concrete instances | Canonical keys, aliases, transitive outer type parameters, fresh nodes/tables, closure, erasure and mutation rejection |
| Checked error records | Canonical identity, exact E, lexical owner, noncompletion and substituted metadata corruption |
| Try Core | Positive subject/tag guards, return descriptor/type, Err last-use payload roots and missing-root rejection |
| Panic Core/native | String terminal operand, liveness, outgoing slot, noreturn call, frame evidence and corrupt metadata |
| Representation and ABI | Independent emitted descriptor words, void slot, reference masks and a handwritten Result caller |
| Lifetime | Strong child survival, dead Result parent observation, source retention mutant, missing trace/sweep mutants and host weak references |
| Output and artifacts | UTF-8/NUL bytes, partial write, bounded EINTR, fd/storage failure, nonallocating native reporter, build nonexecution and relocation |

Verifier mutation cases are separate from source acceptance fixtures. Producer
metadata is not used as an expected result oracle for descriptor bytes or
observed program output.

## Lifetime observations

The generic Result/Box fixture performs 4,006 allocations within a 4,096-byte
heap cap. Normal-trigger GC performs 41 collections and reclaims 3,920 blocks;
stress GC performs 4,007 collections and reclaims 4,002 blocks. Both observe
reclaimed region reuse and keep the extracted string payload valid after its
Result parents become dead. A deliberately retained parent is rejected by the
independent heap observer.

The host weak-reference process tracks and observes reclamation of all 30,003
allocated generic data/Result objects after execution. These measurements are
distinct from native collector counters and process memory usage.

## Migration and limits

[Migration ledger](../tests/v08-migration.json) preserves source/file hashes,
annotation changes, and selected-function-binding expectation changes. Existing
regression groups remain enabled; prior release tags and records are unchanged.

The implementation adds no generic interface/method/implement, constraint,
type inference, recovery, stack trace, or defer guarantee. Exhaustive behavior
over unbounded source depth, OS termination, and uncatchable host exhaustion is
not established by bounded tests. At this implementation checkpoint, main
integration and release were pending an explicit release request.
