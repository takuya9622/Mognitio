# v0.7.0 release validation

Date: 2026-09-23

Version 0.7.0 adds nominal immutable data, unified branches, and interface
contracts with concrete methods and dynamic dispatch. This is a source release
for Linux amd64, using SBCL and its bundled ASDF, UIOP and SB-POSIX facilities.
Generated ELF executables run without SBCL or libc; the compiler does not
require an external assembler, linker or third-party Lisp libraries.

## Candidate and reproduction

Implementation baseline: `13bba3ec45d6c19a11a3d2208655285c991df8db`.
Release preparation updates documentation and content checksums only. Compiler,
test sources, ASDF version `0.7.0` and native ABI v4 are unchanged.
The release-preparation PR records the exact committed candidate and full-suite
result. Its tree must match the version candidate and the main merge commit;
the immutable annotated `v0.7.0` tag identifies that main merge commit.

```sh
sbcl --noinform --script scripts/test.lisp
git diff --check
sha256sum -c verification/SHA256SUMS
```

The reviewed implementation passed 156 groups, 17,510 assertions and 1,501
child processes with zero failures. The committed release candidate receives
the same complete regression gate before integration. UTF-8/LF, final newlines,
Markdown links/fences and the delivered checksum manifest are also checked.

## Behavior and coverage

- Nominal structs and enums, immutable fields/payloads, aliases and value rebinding.
- `branch when` and `branch on`, with ordered evaluation, typed payload binding,
  exhaustiveness and defined early-exit behavior.
- Interface requirements spelled `let name = function(...): Type;`, concrete
  and inherent implementations, implicit `this`, contract-specific dispatch.
- Host and native collection retain reachable aggregate/interface graphs and
  reclaim unreachable data. Tests observe actual reuse and transitive lifetime.
- Independent metadata, root, ABI, static-layout, padding and corruption checks,
  plus historical arithmetic/text/function/loop, artifact and I/O regressions.

The [initial development record](v0.7.0.md), [review correction record](v0.7.0-review.md)
and [test matrix](../tests/README.md) provide the acceptance mapping and measured
evidence. Current README programs and checked-in examples run in the full suite.
Prior checkpoint measurements remain historical; they are not rewritten as
measurements of the release candidate.

## Compatibility and limits

`if` is replaced by `branch when`; `match` is reserved and rejected. New reserved
words are `type`, `struct`, `enum`, `interface`, `implement`, `against`, `this`,
`branch`, `when`, `on`, and `match`. Rename conflicting bindings. Comma-separated
lists accept one trailing comma. Bare member access is parsed as field access;
unknown fields, including bare method references, fail semantic checking.

The pre-release interface spelling `function name(...): Type;` is rejected at
parse time. Ordinary function expressions and implementation methods require
bodies. Requirements create no function values; conformance and dispatch are
unchanged by the spelling revision. Entry results remain `bool`.

Mutable fields, aggregate equality, recursive types/calls, generics, modules
and new I/O facilities are outside this release. Other hosts and native targets
are unverified. Finite samples and bounded heap tests do not prove every input,
uncatchable OS/resource failure or concurrent filesystem change.
